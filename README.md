# 节奏长跑 · Rhythm Run 3D

一个用键盘就能玩的 3D 卡通长跑小游戏。**A / D 左右交替踩步**，每次点击的间隔越均匀越省力，路过补给点记得按 `↑` 喝水、`↓` 吃东西，跑到 1000 米终点。

纯前端静态页面，零构建、零运行时依赖（three.js 已内置在 `vendor/`），双击 `index.html` 就能玩。

## 玩法

| 操作 | 说明 |
| --- | --- |
| `A` / `←` `D` / `→` | 左右脚交替踩步（同侧连点会「错步」，扣体力） |
| `↑` / `W` | 补给点喝水（水分补满） |
| `↓` / `S` | 补给点吃东西（体力 +28，但要慢跑一段） |
| `R` | 重开一局 |
| `M` | 静音 |
| 手机 | 点屏幕左半边 = 左脚，右半边 = 右脚；底部补给条可直接点左右两栏 |

### 三条数值

1. **体力上限（金色）**——决定最高速度（16 ~ 26 km/h）。会随着跑动缓慢下降，越到后面越跑不快；吃东西能回一点。
2. **体力（绿色）**——每一步都在消耗，同时每秒快速回复，所以它会上下起伏。
   **判定的不是「踩在某个节拍上」，而是「每次点击的间隔是不是差不多」**：系统记着你最近的平均间隔，某一下跟平均值的偏差够小就算稳住，这一步的体力打 0.78 折；连着稳住还会叠「节奏稳 ×N」，越稳越省力、还有点加速。忽快忽慢、抢拍、同侧连点都会让体力掉得明显。
3. **水分（蓝色）**——随时间一直掉，掉光后体力回复变慢、消耗变高。每 200 米一个补给点，别连着漏掉。

跑到体力上限归零会**力竭退赛**，所以别一路狂点：快一点只多一点点速度，但体力和体力上限都会烧得很快。

### 补给点

每 200 米一个（200/400/600/800 m），每站各有一次「喝水」和一次「吃东西」的机会，进入范围后屏幕底部会出现带按键提示的补给条：

- 喝水：1.1 秒，速度降到 76%，水分补满 + 体力 8
- 吃东西：2.8 秒，速度降到 40%（变成慢跑），体力 +28、体力上限 +4.5，但会口渴（水分 -6）

补给期间步频不会衰减，所以不会因为吃东西直接站住。

## 文件结构

```
index.html          页面 + 样式（两个 canvas：3D 场景 / 2D HUD）
vendor/three.min.js three.js r149（UMD 版本，已内置）
src/logic.js        游戏核心逻辑：纯函数，无 DOM 依赖，可在 node 里跑数值仿真
src/scene.js        3D 世界：角色骨架、地形、补给拱门、终点、粒子、相机
src/hud.js          HUD 层：状态条、进度、补给按键提示、标题与结算
src/game.js         主循环、输入、音效
tune.js             数值平衡仿真（node tune.js）
```

## 开发

```bash
# 平衡性仿真：用真实 logic.js 跑「稳如钟摆 / 普通玩家 / 手抖 / 忽快忽慢 / 抢拍 / 慢摇 / 乱按」
node tune.js
```

调参都在 `src/logic.js` 顶部的 `C` 里（参考步频 `IDEAL`、稳定判定 `STEADY_DEV`、体力消耗 `COST_BASE`、回复 `REGEN`、速度上限 `VMAX_*`、补给效果等），改完跑一遍 `tune.js` 就能看到结果。

当前手感（`node tune.js` 实测）：

| 玩家 | 结果 |
| --- | --- |
| 稳定节奏 | 154 秒完赛，体力最低 62 |
| 手比较稳 | 154 秒完赛，体力最低 52 |
| 手抖 / 忽快忽慢 | 163 秒勉强完赛，或 966 米力竭 |
| 一直抢拍 | 891 米力竭 |
| 疯狂乱按 | 816 米力竭 |
| 慢慢摇 | 229 秒完赛，体力一直是满的 |

镜头参数在 `src/scene.js` 顶部的 `CAM` 里。

## 技术要点

- 角色没有用骨骼动画，而是用一组 `Object3D` 转轴做正向运动学：髋/膝、肩/肘按跑步相位摆动，膝盖在腿后摆时弯曲，配合躯干前倾和上下起伏。
- 地形是程序化的：路面/草地贴图用 canvas 现画，树木灌木按 `WORLD_SPAN` 循环回收，所以 1000 米赛道不需要重复建模。
- 逻辑层（`logic.js`）完全不碰渲染，`tune.js` 直接 `require` 它做几千帧仿真来调平衡。
- 所有节奏判定与体力回复都走同一个「游戏内时间」（按帧累加，单帧最多 0.06 秒），掉帧时不会出现「判定用真实时间、回复用帧时间」两套时钟错位。
