# 节奏长跑 · Rhythm Run 3D

一个能两个人抢同一个键盘玩的 3D 卡通长跑小游戏：**左右交替踩步**，踩得越快越费体力，体力见底就只能走一会儿。跳过障碍、在补给点喝水吃香蕉，和三个 AI 对手抢 1000 米。

纯前端静态页面，零构建、零运行时依赖（three.js 已内置在 `vendor/`），双击 `index.html` 就能玩。

## 玩法

### 体力：唯一的省力办法是踩慢一点

- 体力是**按「当前步频」每帧扣的功率**，不是每按一次扣一坨。踩得越密，每秒烧得越快（`COST_RATE` / `COST_EXP`）。
- 每秒有基础回复（`REGEN = 10.6`），踩到 **0.31 秒左右**刚好收支平衡，这就是「经济步频」。
- **所以「想快」和「想省」是同一个旋钮**：想冲刺就踩快，付出体力；想苟着就用慢一点的频率跑，速度慢但不累。
- 没有节拍判定、没有连击、没有「节奏稳」加成，也不再提示「太急 / 太慢」。
- 体力消耗是**按游戏内时间积分**的，掉帧不会放大：5 fps 和 60 fps 同样手速扣得一样多（以前是单步扣费，低帧下同样手速会扣到 3 倍，这是「一下就空」的真凶）。

有补给站正常喝水吃香蕉的情况下，不同手速能撑多久：

| 手速 | 步频 | 速度 | 第一次见底 |
| --- | --- | --- | --- |
| 0.20 秒/步 | 300 步/分 | 31.4 km/h | 10 秒 |
| 0.22 秒/步 | 273 步/分 | 29.1 km/h | 16 秒 |
| 0.24 秒/步 | 250 步/分 | 27.2 km/h | 34 秒 |
| 0.26 秒/步 | 231 步/分 | 25.5 km/h | 73 秒 |
| 0.28 秒/步 | 214 步/分 | 24.0 km/h | 全程不见底 |

### 体力见底 = 被迫走路

体力掉到 0 不会退赛，而是**进入走路状态**：

- 速度被锁在 7 km/h，体力以 **2 倍**速度恢复
- 走路时踩得再快也不掉体力，但也不加速
- 体力回到 **40**、且已经走了至少 **2.6 秒**，才能重新跑起来（不然会出现「站起来又趴下」的一秒一切换）
- 右上卡片底部会亮一行红字「体力见底 · 走一走」，不会让人以为卡了

从见底到缓过来大约 2.5 秒，速度掉下去再升上来还要 1~2 秒，实际损失 20 米上下。想避免就早点放慢节奏。

### 三条数值

| 条 | 说明 |
| --- | --- |
| 体力上限（黄） | 决定最高速度（21.2 ~ 26.2 km/h）。会缓慢下降，跑太快掉得更快；吃香蕉能回一点 |
| 体力（绿） | 按步频每秒消耗 + 每秒回复。**归零就走路** |
| 水分（蓝） | 随时间下降，掉光后体力回复只剩 45%、消耗还涨 30%。每 200 米一个补给点 |

### 键位

**单人**（标题页按 `空格`）

| 操作 | 键 |
| --- | --- |
| 左右交替踩步 | `A` / `D`（或 `←` `→`） |
| 起跑 / 跳跃 | `空格`（倒计时中按一次起跑，跑步中按跳跃） |
| 喝水 | `W` 或 `↑` |
| 吃香蕉 | `S` 或 `↓` |
| 用道具 | `1` `2` |
| 重开 / 静音 | `R` / `M` |

**双人**（标题页按 `回车`）

| | P1 | P2 |
| --- | --- | --- |
| 左右踩步 | `A` / `D` | `←` / `→` |
| 起跑 / 跳跃 | `W` | `↑` |
| 补给 | `S` | `↓` |
| 用道具 | `1` / `2` | — |

双人只有 4 个键，所以补给合并成一个：**按一次先喝水，水够了再按就吃香蕉**。双人模式没有道具赛（键位不够），纯节奏对抗；三个 AI 对手照样在场上。

鼠标 / 触摸：点画面左半边 = 左脚，右半边 = 右脚，左下圆按钮 = 跳跃，底部补给条和右下道具槽都能直接点（作用于 P1）。

> **键盘没反应？** 先点一下画面。预览面板 / iframe 里键盘焦点默认在页面上层，页面收不到按键。
> 键位判定用的是 `event.code`（物理键位），中文输入法开着也能正常跑。

### 起跑：越接近「GO」越猛

按空格（双人按 `W` / `↑`）开始 3.2 秒倒计时，GO 的瞬间再按一次起跑。倒计时 **3 / 2 / 1 每一下都有音效**（C5 → E5 → A5，一级比一级高），GO 时是一记 C6 和弦：

- 距离 GO 越近（±0.5 秒窗口）→ 起步加速越强：完美起跑直接顶到 16 km/h，额外给 1.4~2.9 秒加速
- 倒计时还剩 0.62 秒以上就按 → 抢跑，0.55 秒内速度被摁住
- 一直不按 → 只有 15% 起步质量

### 障碍

每 56~88 米一个，自动避开补给点前后 36 米，三种随机：

| 障碍 | 形状 | 处理 |
| --- | --- | --- |
| 跨栏 hurdle | 白横杆 + 红白立柱 | 空格跳过 |
| 锥桶 cone | 橙色路障锥 | 空格跳过 |
| 水坑 puddle | 蓝色水面 + 白边 | 空格跳过（踩到会溅一身） |

跳跃滞空 0.62 秒。48 米内弹预警、16 米内转红。撞上掉到 38% 速度并扣体力。

### 对手与道具（单人）

三个 AI 对手（阿虎 / 小鹿 / 老陈）各有不同基础速度、避障成功率和偷袭倾向，会自己跳障碍、经过补给点时朝你扔水瓶。

道具 2 个槽（`1` `2`）：

| 道具 | 来源 | 效果 |
| --- | --- | --- |
| 加速 | 补给点随机 55% | 5 秒速度 ×1.26 |
| 干扰 | 补给点随机 45% | 前方 48 米内最近的对手 3.5 秒内左右键变上下键 |
| 空水瓶 | 喝完水自动获得 | 朝前方对手投掷，命中减速 2 秒 |
| 香蕉皮 | 吃完香蕉自动获得 | 丢在脚下，后面踩到的对手打滑 1.7 秒 |

### 结算

名次决定评级：第 1 名 `S`、第 2 名 `A`、第 3 名 `B`、第 4+ 名 `C`。双人模式会显示谁先到终点、两人各自的名次。400 秒跑不完强制结束。

## 文件结构

```
index.html          页面 + 样式（两个 canvas：3D 场景 / 2D HUD）
vendor/three.min.js three.js r149（UMD 版本，已内置）
src/logic.js        游戏核心逻辑：纯函数，无 DOM 依赖，可在 node 里跑数值仿真
src/scene.js        3D 世界：角色骨架、对手、障碍、道具、地形、补给拱门、终点、粒子、相机
src/hud.js          HUD 层：状态条、进度与对手小点、名次、道具槽、跳跃按钮、双人面板、标题与结算
src/game.js         主循环、输入分流（单人 / 双人）、音效
tune.js             数值平衡仿真（node tune.js）
```

## 开发

```bash
node tune.js     # 跑整场比赛仿真，对比不同手速的玩家 & 双人两套状态
node drain.js    # 只测体力曲线：固定手速下能撑多久、会走几次
```

调参都在 `src/logic.js` 顶部的 `C`：

- `COST_RATE` / `COST_EXP` —— 参考步频下每秒消耗、以及「踩快有多费」的陡峭程度，这两项决定「多快算透支」
- `REGEN` —— 自然回复，和上面两项一起决定经济步频落在哪
- `WALK_SPEED` / `WALK_EXIT` / `WALK_MIN` / `WALK_REGEN` —— 被迫走路的强度、恢复门槛、最短走路时间
- `VMAX_MIN` / `VMAX_SPAN` / `TOTAL_DRAIN` —— 速度上限与上限衰减
- `SPD_IV` / `CAD_CAP` —— 「多少步频算满速」和「再快也不涨速」的封顶，把速度和消耗拆开调
- `EAT_STAMINA` —— 一根香蕉回多少体力（现在是 40）
- `COUNTDOWN` / `START_WINDOW` / `START_FALSE` —— 起跑判定
- `JUMP_*` / `OBST_*` —— 跳跃与撞击

当前手感（`node tune.js` 实测，全程 1000 米，障碰随机生成，多跑几次会有小幅浮动）：

| 玩家 | 结果 |
| --- | --- |
| 稳节奏（0.27s） | 156~157 秒完赛，**第 1 名**，中途见底一次、走 2.6 秒 |
| 普通手速（±8%） | 156~157 秒完赛，**第 1 名**，走 2.6~3.4 秒 |
| 手抖（±25%） | 155~159 秒完赛，**第 1 名**，走 8~10 秒 |
| 巡航（0.30s） | 163~166 秒完赛，第 2~3 名 —— 省力但太慢 |
| 慢慢摇（0.36s） | 202 秒完赛，第 4 名 |
| 疯狂乱按（0.16s） | 258 秒完赛，第 4 名，190 秒都在走 |

双人自检：0.26 秒步频 159 秒完赛（第 2 名，走 4 次），0.31 秒步频 175 秒（第 5 名，一次没走）。

也就是说：**踩快能赢但会透支，踩慢很省但会输** —— 这就是这一局要权衡的东西。

## 技术要点

- `players` 数组里第 0 个就是 `s` 本身（P1 的状态直接挂在 `s` 上），P2 是 `s.p2`，同一套 `stepRunner()` 逻辑。这样渲染层读 `s.distance` / `s.stamina` 的老代码完全不用改。
- 双人同框靠相机自适应：以**落后者**为基准，按两人的分差把镜头往后 (`behind`) 和往侧 (`side`) 拉，分差越大视野越宽，两个人永远都在画面里。
- 障碍用「滚动分配」的模型池：遍历视野内的障碍依次塞进池子，而不是「池子第 i 个对应第 i 个障碍」。之前池子只有 3 个、按索引一一对应，**第 4 个之后的障碍根本不渲染** —— 这就是「很多障碍没显示出来」的原因。同时水坑从贴地浅色改成深蓝 + 白边，跨栏/锥桶尺寸也重新对过。
- 补给拱门只保留远离镜头那一根立柱，近侧改成矮补给箱：原来近侧立柱正好夹在镜头和跑者之间，每过一个补给站都会把画面挡掉半秒。
- 键位用 `KeyboardEvent.code`（`KeyA` / `Space` / `ArrowUp`…）而不是 `key`，中文输入法激活时 `key` 会变成 `Process`，用 `code` 才不会漏键。
- 角色没有用骨骼动画，而是一组 `Object3D` 转轴做正向运动学：髋/膝、肩/肘按跑步相位摆动，膝盖在腿后摆时弯曲。玩家、P2、三个对手共用同一个 `buildRig()` 工厂，只是配色不同。
- 体力消耗和回复都按「游戏内时间」积分（按帧累加，单帧最多 0.06 秒）：消耗是功率 × dt，不是按按键次数扣费，所以掉帧时不会凭空多扣。
- `SPD_IV`（多少步频算满速）和 `IDEAL`（消耗的参考步频）是两个独立常量：把「速度」和「体力」拆开调，才能做到「慢跑能跟住 AI、想赢必须透支」。
