# 节拍长跑 · Rhythm Run 3D

一个用鼠标键盘就能玩的 3D 卡通长跑小游戏。**A / D 左右交替踩步**，踩准节拍才省力，路过补给点记得喝水、吃东西，跑到 1000 米终点。

纯前端静态页面，零构建、零运行时依赖（three.js 已内置在 `vendor/`），双击 `index.html` 就能玩。

## 玩法

| 操作 | 说明 |
| --- | --- |
| `A` / `←` `D` / `→` | 左右脚交替踩步（同侧连点会「错步」，扣体力） |
| `↑` / `W` | 补给点喝水（水分补满） |
| `↓` / `S` | 补给点吃东西（体力 +26，但要慢跑一段） |
| `R` | 重开一局 |
| `M` | 静音 |
| 手机 | 点屏幕左半边 = 左脚，右半边 = 右脚；补给面板可直接点 |

### 三条数值

1. **体力上限（金色）**——决定最高速度（16 ~ 26 km/h）。会随着跑动缓慢下降，越到后面越跑不快；吃东西能回一点。
2. **体力（绿色）**——每一步都在消耗。屏幕下方的节拍条上有一段金色区间，**踩在金色区间里每一步只花 0.9 倍体力**，连续踩准还能叠连击，连击越高越省力、还略微加速。乱按/抢拍会让体力暴涨消耗，见底后只能慢跑。
3. **水分（蓝色）**——随时间一直掉，掉光后体力几乎不再回复。160 米左右就有一个补给点，别连着漏掉。

跑到体力上限归零会**力竭退赛**，所以别一路狂点。

### 补给点

每 200 米一个（200/400/600/800 m），每站各有一次「喝水」和一次「吃东西」的机会：

- 喝水：1.2 秒，速度降到 72%，水分补满 + 体力 8
- 吃东西：3.4 秒，速度降到 30%（很慢），体力 +26、体力上限 +4.5，但会口渴（水分 -6）

## 文件结构

```
index.html          页面 + 样式（两个 canvas：3D 场景 / 2D HUD）
vendor/three.min.js three.js r149（UMD 版本，已内置）
src/logic.js        游戏核心逻辑：纯函数，无 DOM 依赖，可在 node 里跑数值仿真
src/scene.js        3D 世界：角色骨架、地形、补给拱门、终点、粒子、相机
src/hud.js          HUD 层：状态条、进度、节拍条、标题与结算
src/game.js         主循环、输入、音效
tune.js             数值平衡仿真（node tune.js）
```

## 开发

```bash
# 平衡性仿真：用真实 logic.js 跑「完美节奏 / 随手按 / 抢拍 / 乱按」四种玩家
node tune.js
```

调参都在 `src/logic.js` 顶部的 `C` 里（理想步频 `IDEAL`、体力消耗 `COST_BASE`、回复 `REGEN`、速度上限 `VMAX_*`、补给效果等），改完跑一遍 `tune.js` 就能看到结果。

目标手感：完美节奏约 165 秒完赛，全程体力吃紧但不至于见底；持续抢拍大约 90 秒就会力竭。

镜头参数在 `src/scene.js` 顶部的 `CAM` 里。

## 技术要点

- 角色没有用骨骼动画，而是用一组 `Object3D` 转轴做正向运动学：髋/膝、肩/肘按跑步相位摆动，膝盖在腿后摆时弯曲，配合躯干前倾和上下起伏。
- 地形是程序化的：路面/草地贴图用 canvas 现画，树木灌木按 `WORLD_SPAN` 循环回收，所以 1000 米赛道不需要重复建模。
- 逻辑层（`logic.js`）完全不碰渲染，`tune.js` 直接 `require` 它做几千帧仿真来调平衡。
